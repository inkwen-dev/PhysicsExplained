## 加载与失败

- `Banner.tsx`在当前设备选择一个尺寸，然后接近视口600px时加载。每个横幅有独立iframe文档，隔离平台全局`atOptions`和`document.write`。
- 无广告时外壳高度0，无标签、边框和占位。图片实际加载或广告子框架有非空响应时才显示“Advertisement”；超时20秒清理。外壳提前收起而非先展示大空白，成功填充仍可能使后续内容移动，不能称为CLS为0。
- 跨域子框架无法读取其内部素材；load加非空地址只能作为交付信号，不能保证内部一定有可见广告。平台没有已核实的统一no-fill回调；若出现跨域空白响应，须补充供应商信号后再处理，不能把脚本onload作为成功。实际展示仍以视觉验收为准。
- 原生广告观察图片或有实际文案的链接，脚本加载本身不算填充；失败/超时保留零高度。原生403不在本轮排障范围，不联系客服。
- Social Bar代码只在允许页面加载一次。平台没有已核实的SPA卸载接口，启用时站内普通链接采用完整文档导航，避免广告浮层从文章残留到About/404；Ctrl/Command点击、外链和同页锚点保持原行为。
- Social Bar并非浏览器订阅通知。若实际素材遮挡阅读、频繁弹出或伪装系统消息，应单独停用；不以后台Active代替预览验收。

## 更新和停投

构建时环境变量（修改后须重新部署）：

- `NEXT_PUBLIC_ADS_ENABLED=false`：总停投，开发默认关闭。
- `NEXT_PUBLIC_BANNERS_ENABLED=false`：只停横幅。
- `NEXT_PUBLIC_SOCIAL_BAR_ENABLED=false`：只停Social Bar。
- 原生按`positions`现有各位置开关控制。

替换广告代码：在同站后台核对GET CODE → 更新config公开参数与本表 → 构建/静态校验 → 按[上线流程](01-Cloudflare上线与更新流程.md)发布 → 实测手机、桌面、无填充、导航、About/404 → 写[上线记录](02-上线记录.md) → 提交推送。不能只推送Git而不部署。不要把密码、授权码或令牌放入仓库。

真实请求、真实展示、平台展示统计、预估收益、实际到账分开记录。本轮验收结果见上线记录，不保证广告填充率或收益。
