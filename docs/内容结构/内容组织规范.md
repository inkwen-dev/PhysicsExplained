# 内容组织规范

> **目的**：规范内容目录结构、Frontmatter格式、文章结构和链接方式  
> **适用范围**：所有文章内容

---

## 一、目录结构

```
content/
├── categories/              # 分类元数据（6个分类）
│   ├── classical-mechanics.md
│   └── ...
├── subcategories/           # 子分类元数据（每个分类4个子分类）
│   ├── classical-mechanics/
│   │   ├── kinematics.md
│   │   └── ...
│   └── ...
└── topics/                  # 文章内容（目标100篇）
    ├── classical-mechanics/
    │   ├── kinematics/
    │   │   ├── why-do-objects-fall.md
    │   │   └── ...
    │   └── ...
    └── ...
```

**原则**：
- 保持三层结构：`category/subcategory/article`
- 每个子分类下建议10-20篇文章
- 文件路径与分类结构一致，便于维护

## 二、文章 Frontmatter 规范

### 2.1 Frontmatter 格式

**Frontmatter** 是 YAML 格式的元数据，位于 Markdown 文件的开头，用 `---` 分隔。

**示例**：
```yaml
---
title: "文章标题"
slug: "article-slug"
category: "classical-mechanics"           # 必需：分类ID
subcategory: "kinematics"                  # 必需：子分类ID
shortAnswer: "简短答案（1-2句话）"
publishedAt: "2024-01-15"                 # 必需：发布日期（YYYY-MM-DD）
updatedAt: "2024-01-20"                   # 可选：最后更新日期
tags:                                      # 可选：标签数组（3-8个）
  - "motion"
  - "gravity"
  - "physics"
relatedTopics:                             # 可选：相关文章slug数组（3-8篇）
  - "what-is-velocity"
  - "what-is-acceleration"
  - "how-does-gravity-work"
metaTitle: "SEO标题（可选）"
metaDescription: "SEO描述（可选）"
keywords:                                  # 可选：关键词数组
  - "why objects fall"
  - "gravity"
  - "falling objects"
---
```

**必需字段**：`title`, `slug`, `category`, `subcategory`, `shortAnswer`, `publishedAt`

**推荐字段**：`tags`, `relatedTopics`, `updatedAt`, `metaTitle`, `metaDescription`, `keywords`

## 三、文章内容结构

每篇文章必须包含以下部分（按顺序）：

```markdown
# [文章标题]（H1，直接回答问题）

## Short Answer（必需）
[1-2句话的简短答案，与 frontmatter 中的 shortAnswer 一致]

## Detailed Explanation（必需）

### Background（必需）
[背景介绍，2-3段，解释为什么这个问题重要]

### Scientific Principles（必需）
[物理原理解释，使用编号列表，基于物理定律和理论]

### Real Examples（必需）
[真实案例，3-5个具体例子，使用项目符号列表]

## Practical Applications（必需）

### How It Works in Daily Life（必需）
[日常生活中的应用，使用编号列表]

### Scientific Experiments & Demonstrations（必需）
[可以做的实验和演示，使用项目符号列表]
```

**各部分要求**：
- **Short Answer**：1-2句话，直接回答问题
- **Background**：2-3段，解释问题的背景和重要性
- **Scientific Principles**：基于物理原理，使用编号列表（有顺序）
- **Real Examples**：3-5个具体、真实的例子，使用项目符号列表
- **How It Works in Daily Life**：可操作的应用，使用编号列表（步骤有顺序）
- **Scientific Experiments & Demonstrations**：实验和演示，使用项目符号列表（无顺序）
- **内部链接**：在正文中自然添加内部链接（每1000字2-5个）

## 四、文章链接与引用

### 4.1 内部链接规范

**方式一：使用 Markdown 链接（推荐）**
```markdown
更多信息请参考 [重力](how-does-gravity-work) 和 [速度](what-is-velocity)。
```

**方式二：使用 frontmatter 的 relatedTopics**
- 系统自动生成"相关文章"模块
- 在文章底部显示相关文章列表

### 4.2 引用规范

- 使用 `relatedTopics` 字段维护强相关文章（3-8篇）
- 正文中使用 Markdown 链接引用其他文章
- 系统自动解析链接，生成可点击的导航

## 五、标签系统

### 5.1 标签分类

- **主题标签**：motion, gravity, electricity, light, quantum
- **应用场景**：everyday, experiments, technology
- **难度级别**：beginner, intermediate, advanced
- **内容类型**：theory, practical, demonstration

### 5.2 标签使用原则

- 每篇文章3-8个标签
- 优先使用现有标签，保持一致性
- 定期审查标签，合并相似标签

---

## 六、扩展性考虑

### 6.1 100篇文章的组织

- **分类层**：6个分类（每个分类15-20篇文章）
- **子分类层**：每个分类4个子分类（每个子分类3-5篇文章）
- **文章层**：按主题组织，便于查找和维护

### 6.2 维护建议

- 定期检查 `relatedTopics` 链接的有效性
- 统一标签命名规范
- 保持 frontmatter 字段一致性
- 使用脚本验证文件路径与分类一致性
