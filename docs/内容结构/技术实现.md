## 一、Frontmatter 解析

### 1.1 什么是 Frontmatter？

**Frontmatter** 是 YAML 格式的元数据，位于 Markdown 文件的开头，用 `---` 分隔。

**作用**：
- 存储文章的元数据（标题、分类、日期等）
- 不显示在文章正文中
- 通过 `gray-matter` 库解析为 JavaScript 对象

### 1.2 解析实现

项目使用 `gray-matter` 库解析 Frontmatter：

```typescript
// lib/markdown.ts
import matter from "gray-matter";

export function parseMarkdownFile(filePath: string) {
  const fileContents = fs.readFileSync(filePath, "utf8");
  const { data, content } = matter(fileContents);
  // data: Frontmatter 解析后的对象
  // content: Markdown 正文内容
  return { frontmatter: data, content };
}
```

## 二、Markdown 转 HTML

### 2.1 技术方案

项目使用 **`remark` + `remark-html`** 将 Markdown 转换为 HTML：

```typescript
// lib/markdown.ts
import { remark } from "remark";
import remarkHtml from "remark-html";
import remarkGfm from "remark-gfm";      // GitHub Flavored Markdown 支持
import remarkBreaks from "remark-breaks"; // 支持单个换行转换为 <br>

export async function markdownToHtml(markdown: string): Promise<string> {
  const result = await remark()
    .use(remarkGfm)      // 支持表格、任务列表等 GFM 语法
    .use(remarkBreaks)   // 支持单个换行转换为 <br>
    .use(remarkHtml)     // 转换为 HTML
    .process(markdown);
  return result.toString();
}
```

**依赖包**：
- `remark`: Markdown 解析器
- `remark-html`: 将 Markdown AST 转换为 HTML
- `remark-gfm`: 支持 GitHub Flavored Markdown（表格、删除线等）
- `remark-breaks`: 支持单个换行转换为 `<br>` 标签
- `gray-matter`: 解析 Frontmatter

### 2.2 换行支持

**换行规则**：
- **单个换行**：转换为 `<br>` 标签（通过 `remark-breaks` 插件）
- **两个换行**：转换为新段落 `<p>`

**示例**：
```markdown
这是第一行
这是第二行（单个换行，会显示为 <br>）

这是新段落（两个换行，会显示为 <p>）
```

**使用场景**：
- 在段落内需要换行时，使用单个换行
- 需要新段落时，使用两个换行

### 2.3 使用流程

1. **读取文件**：`fs.readFileSync()` 读取 Markdown 文件
2. **解析 Frontmatter**：`gray-matter` 分离元数据和正文
3. **转换 HTML**：`remark().use(remarkHtml).process()` 转换正文
4. **渲染页面**：React 组件中使用 `dangerouslySetInnerHTML` 渲染 HTML

```typescript
// 完整流程示例（lib/content.ts）
const { frontmatter, content } = parseMarkdownFile(filePath);
const htmlContent = await markdownToHtml(content);

// 在 React 组件中使用
<div dangerouslySetInnerHTML={{ __html: article.content }} />
```

### 2.4 样式要求

- 使用 Tailwind CSS 的 `prose` 类提供基础排版样式
- 响应式设计，适配移动端和桌面端
- 清晰的排版，良好的可读性
- 突出显示 Short Answer 部分
- 相关文章模块样式统一

### 2.5 段落间距优化

**问题**：默认Markdown渲染的段落间距不够明显，内容看起来密密麻麻

**解决方案**：在 `app/globals.css` 中自定义 `.prose` 样式，增加段落间距

**段落间距设置**：
- **段落（p）**：`mb-6`（下边距 1.5rem / 24px）
- **行高**：`leading-relaxed`（1.625）
- **标题间距**：
  - H1: `mt-8 mb-6`（上边距 2rem，下边距 1.5rem）
  - H2: `mt-8 mb-4`（上边距 2rem，下边距 1rem）
  - H3: `mt-6 mb-3`（上边距 1.5rem，下边距 0.75rem）
- **列表间距**：`mb-6`（列表之间）
- **列表项间距**：`mb-2`（列表项之间）

**实现代码**（`app/globals.css`）：
```css
@layer components {
  .prose p {
    @apply mb-6 leading-relaxed;
  }

  .prose h1 {
    @apply mb-6 mt-8;
  }

  .prose h2 {
    @apply mb-4 mt-8;
  }

  .prose h3 {
    @apply mb-3 mt-6;
  }
}
```

**效果**：
- 段落之间有明显的视觉分隔（24px间距）
- 标题与段落之间有足够的空间
- 内容更易读，不会显得密密麻麻

## 三、多主题样式实现

### 3.1 主题概念

不仅仅是 light/dark，而是**多种视觉风格主题**，包括：
- 不同的配色方案（背景色、文字颜色、强调色）
- 不同的标题风格（h1-h6 的字体、大小、颜色、装饰）
- 不同的排版风格（行距、段落间距、列表样式）
- 不同的装饰元素（边框、阴影、背景图案）

### 3.2 推荐方案：CSS 变量 + 类名切换

**思路**：使用 CSS 变量定义完整的主题样式，通过切换容器类名改变整个文章样式

**实现步骤**：
1. 在 `globals.css` 中定义多个主题的完整 CSS 变量
2. 为 Markdown HTML 容器添加主题类名（如 `article-theme-default`, `article-theme-elegant`）
3. 使用 CSS 选择器 `.article-theme-xxx .prose` 定义不同主题的所有样式

**示例代码**：

```css
/* globals.css - 定义多个文章样式主题 */

  background: var(--article-bg);

.article-theme-default .prose h1 {

  font-weight: var(--article-h1-weight);

/* 主题2：优雅风格 */

.article-theme-elegant .prose h1 {
  color: var(--article-h1-color);
  font-size: var(--article-h1-size);
  font-weight: var(--article-h1-weight);
  border-bottom: var(--article-h1-border);
```

**在组件中使用**：

```typescript
// 从文章 frontmatter 获取主题
<div className={`prose prose-lg article-theme-${article.theme || 'default'}`}>
  <div dangerouslySetInnerHTML={{ __html: article.content }} />
</div>

// 或者在 frontmatter 中定义主题
// ---
// theme: "elegant"
// ---
```

**主题配置**：
- `article-theme-default`: 默认紫色系，标准标题
- `article-theme-elegant`: 暖色调，大标题+下划线，优雅排版
- `article-theme-minimal`: 黑白极简，小标题，无装饰
- `article-theme-dark`: 深色背景，高对比度

**优点**：简单、性能好、易于维护、可定义完整的视觉风格

## 四、URL 结构规范

### 4.1 推荐URL结构（扁平化）

```
/                                    # 首页
/categories/                          # 分类列表页
/classical-mechanics/                 # 主分类页
/classical-mechanics/kinematics/      # 子分类页
/why-do-objects-fall/                 # 文章详情页（直接使用话题）
/about                                # 关于页
```

**优势**：
- ✅ URL更短，更易记
- ✅ SEO友好（关键词更靠前）
- ✅ 用户友好（直接看到话题）

### 4.2 URL命名规范

**使用连字符（-）**：
- ✅ SEO最佳实践：Google推荐使用连字符作为单词分隔符
- ✅ 主流网站习惯：Wikipedia、Medium、Quora等主流网站都使用连字符
- ✅ 可读性好：URL更易读，用户友好

**单数 vs 复数**：
- **分类列表页**：使用复数（`/categories/`）
- **具体分类页**：使用单数或概念本身（`/classical-mechanics/`）
- **文章页面**：使用问题形式或单数概念（`/why-do-objects-fall/`）

**不使用核心词**：
- ✅ 文章页面直接使用问题形式：`/why-do-objects-fall/`
- ❌ 不使用 `/topic/why-do-objects-fall/`（路径更长）
- ❌ 不使用 `/article/why-do-objects-fall/`（不符合问答类网站定位）

### 4.3 URL示例

- 分类列表：`/categories/`（复数）
- 主分类：`/classical-mechanics/`（单数/概念）
- 子分类：`/classical-mechanics/kinematics/`（概念）
- 文章：`/why-do-objects-fall/`（直接问题）
- 文章：`/what-is-velocity/`（直接问题）

## 六、分类关系和文章数据维护

### 6.1 数据维护方式

**不需要手动维护 JSON 文件**，所有数据通过 **TypeScript 代码动态读取文件系统**：

```typescript
// lib/content.ts

// 1. 读取所有分类（从 categories/ 目录）
export function getAllCategories(): Category[] {
  const categoriesDir = path.join(contentDirectory, "categories");
  const files = fs.readdirSync(categoriesDir);
  return files
    .filter((file) => file.endsWith(".md"))
    .map((file) => {
      const { frontmatter } = parseMarkdownFile(filePath);
      return {
        id: frontmatter.id || path.basename(file, ".md"),
        name: frontmatter.name || "",
        slug: frontmatter.slug || path.basename(file, ".md"),
        description: frontmatter.description || "",
      } as Category;
    });
}
```

### 6.2 数据关系

**分类关系自动建立**：
- 分类：从 `categories/*.md` 读取
- 子分类：从 `subcategories/{category}/*.md` 读取，通过 `categoryId` 关联
- 文章：从 `topics/{category}/{subcategory}/*.md` 读取，通过 `categoryId` 和 `subcategoryId` 关联

**优势**：
- ✅ 无需维护额外的 JSON 配置文件
- ✅ 文件系统即数据结构，直观清晰
- ✅ 添加新文章只需创建文件，无需修改代码
- ✅ 文件路径与分类结构一致，便于验证
